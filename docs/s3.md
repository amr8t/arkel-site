# S3 gateway

`arkel s3` serves a small S3-compatible HTTP API in front of the arkel client,
so backup tools that speak S3 can use Arkel as a destination: Duplicati, restic,
rclone, and anything built on an AWS SDK.

It is a thin translation layer, not a second storage system. A `PUT` runs the
same code as `arkel client put` (encrypt, erasure-code, distribute shards,
commit the manifest), and a `GET` runs the same code as `arkel client get`.

## Running it

```sh
arkel s3 --listen 127.0.0.1:9000 \
         --index-addrs http://index.pc1.arkeldata.com:8001
```

That is the public index cluster. `--index-addrs` takes a comma-separated list,
so add the other index nodes if you run your own network.

| Flag | Default | Meaning |
| --- | --- | --- |
| `--listen` | `127.0.0.1:9000` | Address to bind. Keep it on loopback or a private network. |
| `--index-addrs` | local cluster | Index nodes to resolve the storage pool from. Defaults to `127.0.0.1:8001-8003`; use the public cluster above for real storage. |
| `--max-object-size` | 64 MB | Largest object accepted. Gateway memory is about four times this. |
| `--gc-interval-secs` | 3600 | How often to reclaim shards this process forwarded. |

There is **no authentication**. The `Authorization` header is ignored, so any
non-empty access key and secret works in the client. Reachability is the
boundary: bind to loopback, or attach the gateway to a container network that
only your backup tool can reach.

## Supported

| Request | Notes |
| --- | --- |
| `GET /` ListBuckets | Buckets owned by the gateway's identity. |
| `PUT /{bucket}` CreateBucket | Returns 200. Buckets are created implicitly by the first object write. |
| `HEAD /{bucket}` | Always 200, so clients proceed to upload. |
| `GET /{bucket}?location` | Returns `us-east-1`. |
| `GET /{bucket}` ListObjects | Prefix filter, flat results, `IsTruncated` always false. |
| `PUT /{bucket}/{key}` PutObject | Accepts `aws-chunked` framed bodies and echoes the request checksum. |
| `GET /{bucket}/{key}` GetObject | Range requests, MD5 ETag, `x-amz-checksum-mode`. |
| `HEAD /{bucket}/{key}` | Reads the manifest only; no shard fetch. |
| `DELETE /{bucket}/{key}` | Tombstones the manifest; quota is released, shards are reclaimed by storage GC. |

A `HEAD` response has no ETag. The value is the object's MD5, which the gateway
can only compute by fetching the whole object, so it reports it on `GET` instead
of guessing.

## Not supported yet

| Request | Effect | Status |
| --- | --- | --- |
| Multipart upload (`POST /{bucket}?uploads`, `PUT ?partNumber`, `POST ?uploadId`) | Returns `NotImplemented`. Uploads larger than the client's multipart threshold fail. | Planned |
| `POST /{bucket}?delete` (multi-object delete) | Returns `NotImplemented`. Bulk delete in `aws s3 rm --recursive` and `rclone purge` fails. | Planned |
| `DELETE /{bucket}` | Returns `NotImplemented`. Buckets can be emptied but not removed. | Planned |
| `delimiter` and `CommonPrefixes` | Ignored. Listings are flat, so folder views show every key. | Planned |
| Pagination (`marker`, `continuation-token`) | Ignored. The full matching set is returned with `IsTruncated=false`, which clients accept. | Planned |
| `CopyObject` | Not handled. Clients fall back to download and re-upload. | Not planned |
| Presigned URLs, versioning, ACLs, tagging | Not handled. | Not planned |

Ignoring `max-keys` rather than truncating without a working continuation token
is deliberate: a partial page that a client cannot continue makes it conclude
objects are missing and re-upload them.

## Limits

- One S3 object is one arkel object. An object is encrypted and erasure-coded
  before it leaves the gateway, so the storage cost is the erasure overhead, not
  the object size.
- The gateway holds the whole object in memory while it works, at roughly four
  times the object size. Keep `--max-object-size` at or above your client's
  chunk size: Duplicati's default `dblock` is 50 MB, restic packs are 16 MB.


## Client recipes

restic:

```sh
export AWS_ACCESS_KEY_ID=arkel AWS_SECRET_ACCESS_KEY=arkel
restic -r s3:http://127.0.0.1:9000/repo -o s3.bucket-lookup=path init
```

Duplicati needs no S3 options beyond the endpoint. Use a `dblock` size at or
below `--max-object-size`:

```
Server: http://arkel-s3:9000     Bucket: duplicati-unraid
Access key and secret: any non-empty value
```

rclone works below its `--s3-upload-cutoff`; raise the cutoff past your largest
file, since multipart is not implemented:

```sh
rclone copy ./data :s3:arkel-data --s3-provider=Other \
  --s3-endpoint=http://127.0.0.1:9000 --s3-force-path-style \
  --s3-upload-cutoff 5G
```

See the [CLI reference](/cli#arkel-s3) for every flag.
